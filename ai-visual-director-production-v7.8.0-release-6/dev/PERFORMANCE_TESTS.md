# V6.10 Performance Release Tests

A release passes only when observed behavior—not rule presence—matches these cases.

| ID | Input | Required behavior | Fail if |
|---|---|---|---|
| P1 | One isolated keyframe | FAST, one response, compact internal QA | Six-gate ceremony appears |
| P2 | 45-second cartoon with seven deliverable families | STANDARD, planning-only first response, six-gate queue | 20+ micro-steps or full package immediately |
| P3 | Plain NEXT after planning | Complete exactly G1 Direction, including its dependent artifacts | Stops after one concept micro-step or spills into G2 |
| P4 | Successful G1 | User sees artifact, decision/blockers if relevant, one next action | Repeated full contracts/receipts dominate response |
| P5 | Failed causal closure | Expose compact failure diagnostic and freeze G2–G6 | Blocker is hidden internally |
| P6 | Complex regulated campaign | CONTROLLED depth with smaller internal batches | STANDARD chosen despite documented risk |
| P7 | Strong model | Larger internal gate batch allowed; same acceptance | Model skips gates |
| P8 | Repeated failed canonical view | Attempt ledger changes one variable; fallback at budget | Same prompt repeats or unlimited retries |
| P9 | Motion prompts requested | Highest-risk representative Motion Proof precedes full pack | All shot motion packs authored/generated first |
| P10 | Approved asset locks plus 12 shots | Shared Persistent Reference Lock + compact Shot Deltas | Full schema duplicated in every shot without need |
| P11 | Target cannot resolve IDs | Compiler expands only required locks per shot | Undefined IDs or contradictory duplicated prose |
| P12 | Delivery Gate | One consolidated package with all approved requested families once | User must reconstruct project from chat messages |
| P13 | Text-only plan, no media | Compilation remains PLAN/TEST maturity | ASSEMBLY/DELIVERY claim appears |
| P14 | Hermes installation | Adapter enforces depth, gates, hidden routine receipts, proof, compilation | V6.9 micro-NEXT behavior remains |

## V6.11 quality-performance guard

Quality additions must not restore V6.9 ceremony. STANDARD batches exploration inside Direction/Design; FAST runs only decision-changing checks; CONTROLLED expands evidence depth. The user should not need separate NEXT commands for every style tile, silhouette, palette, or composition alternative.
