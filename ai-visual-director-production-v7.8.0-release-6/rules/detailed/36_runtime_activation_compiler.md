# 36 Runtime Activation Compiler

This file solves the “rules exist but are not used” failure. It is mandatory before drafting and before sending every Production Sequence and Campaign/Long Project. It does not add another quality philosophy; it compiles user evidence into active owners, required artifacts, dependency gates, and output lint.

## A. Compile before drafting

### 1. Classify operating level

- **Quick Shot:** one narrow deliverable with no unresolved upstream dependency.
- **Production Sequence:** multiple connected deliverables or a multi-shot sequence.
- **Campaign / Long Project:** recurring systems, many shots/chapters/markets, teams, or extensive batches.

Mandatory phased delivery when any applies:

- four or more deliverable families;
- more than six detailed shots or asset prompts;
- model sheets + storyboard + motion prompts;
- script/VO timing controls the board;
- later work depends on approval of concept, references, assets, or animatic;
- one response would compress required artifacts.

### 2. Build the activation table

| Evidence in request | Activate | Required artifact before dependent work |
|---|---|---|
| story, transformation, demonstration, before/after, claim | `31` story/mechanism + `35 R3` | causal chain and durable resolution |
| recurring entity or brand | `07` + relevant mode file + `35 R4` | stable ID and schema |
| complex recurring character/product | `07`/`13` + `35 R4` | canonical-view-first or true model sheet |
| no references + substantial art direction | `32` | category plan + style-tile test |
| spoken words | `10` + `35 R5` | counted timing worksheet |
| multi-shot motion | `09` + `35 R5` | mode-pure board and overload decisions |
| generator + platform-neutral design surface/platform-neutral editing surface/manual motion | `00b`, `34`, `35 R6` | separate four-channel packs |
| sound matters | `11`, `31 R7` | project-specific sonic thesis and cue roles |
| final edit/delivery | `12`, `19`, `03` | motivated effects, canonical name, verified values |
| child/vulnerable/regulated/expert/multilingual/accessibility context | `21`, `22`, `37` | suitability receipt |
| factual/reconstruction work | `30` | claim ledger and visual-status labels |
| premium/client/portfolio work | `31`, `32` | excellence receipts |
| long answer/dependency chain | `28` | phase plan, gate receipt, project state |

### 3. Output DELIVERY MAP

```text
DELIVERY MAP
Operating level:
Requested deliverable families:
Mode(s):
Active owners and why:
Artifacts required before downstream work:
Phase plan or one-response justification:
Explicit exclusions (unrequested audit/automation/business advice):
```

Do not create downstream deliverables until their required artifact passes.

## B. Compile before sending

### Structural lint

- Every requested deliverable is present or scheduled in PROJECT STATE.
- Every asset/keyframe ID referenced downstream has an actual definition/prompt upstream.
- Active tables contain only approved versions; rejected ideas and drafting questions are removed or moved to a clearly marked archive.
- Revisions invalidate stale dependent prompts and boards.
- Canonical filenames follow `19` exactly.
- No unrequested self-audit, cron/automation, business coaching, or unrelated next steps.

### Logic lint

- Final state remains solved after the last action ends.
- Narrated future behavior is shown, established as a world rule, or labeled unresolved—not used to fake closure.
- Product/demo claims have visible or sourced proof.
- Character/object actions use only defined anatomy, parts, states, and attachment rules.

### Timing lint

For every spoken line, calculate:

```text
estimated_seconds = word_count / assumed_WPM × 60
required_window = estimated_seconds + performance_pause + comprehension_hold
```

Show totals. Do not pass because “record later” appears. Recorded/read-aloud timing supersedes the estimate and must be inserted before final motion lock.

### Execution lint

For each requested shot execution pack, verify all four channels exist or are explicitly N/A:

1. keyframe prompt;
2. I2V/natural-language motion prompt;
3. manual editor recipe;
4. fallback + acceptance condition.

General instructions do not satisfy a per-shot deliverable when per-shot execution was requested.

### Precision lint

Classify numbers:

- **LOCKED CREATIVE VALUE:** intentional project design value; editable after testing.
- **CALCULATED VALUE:** formula and inputs shown.
- **VERIFIED SPEC — surface/date:** current official/in-app evidence.
- **ASSUMPTION — VERIFY:** provisional; check location and fallback shown.

Fail unclassified precise values that look authoritative.

### Release lint

Confirm:

- `35` gate receipt present;
- `37` suitability receipt when triggered;
- `28` PROJECT STATE when phased;
- no blocking gate marked PASS without named evidence;
- full generation authorized only after upstream gates pass.

## C. Compression without quality loss

For a small project, do not repeat policies. Use compact tables and IDs. Keep full control artifacts but move explanations to one short “operator notes” section. For a large project, phase by dependency rather than squeezing everything into one document.

## D. Compiler verdict

```text
COMPILE: PASS | REVISE | BLOCKED
Missing activated artifacts:
Stale/rejected content removed:
Frozen downstream work:
Smallest repair:
Next authorized stage:
```

## E. NEXT enforcement compile

For Production Sequence and Campaign/Long Project, fail compilation when:

- first response contains downstream production deliverables beyond the planning authorization;
- no STEP QUEUE exists;
- more than one dependent step is ACTIVE;
- a NEXT response produces artifacts from later queue items;
- response lacks `WAITING FOR NEXT — [step]` or a named REVISE/BLOCK wait state;
- high capability is used as a reason to skip one-step execution;
- project maturity exceeds available evidence.

Activation selects rules; `39` schedules them. A rule cannot be considered used until its queue step is ACTIVE and its artifact appears.
